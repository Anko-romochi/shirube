# SHIRUBE 1.0.0

Codex向けの「主張と根拠の地図」。複数資料の引用、読んだ範囲、依存する原典、未解決事項、次に読む資料、前回結論との差分を残します。機械検証は原文と形式の整合を扱い、意味的な支持・史実・原典の独立性を保証しません。

## Codexで使う

配布ZIPを展開し、shirubeフォルダを対象プロジェクトの`.agents/skills/`へ置きます。同名フォルダがあれば先に別の場所へ退避し、上書きしません。個人の全プロジェクトに適用する場合は、ユーザーフォルダの`.agents/skills/`を選べます。正式な配置場所は[OpenAIのSkill説明](https://learn.chatgpt.com/docs/build-skills)を確認してください。Skillが一覧に出なければCodexを再起動します。

Codexで`$shirube`を指定し、例えば次のように依頼します。

> 提供資料を照合して、何が確認でき、何が未確定か、次に何を読むべきかを主張と根拠の地図にしてください。前回メモとの差も示してください。新しい調査フォルダへ保存してください。

初回はこのフォルダをそのまま指定し「SKILL.mdを読み、架空例を新しい出力先で試す」と依頼しても構いません。検索・閲覧・並列担当はCodexで利用でき、許可されたものだけを使います。helperはネット接続・資料取得・外部送信を行いません。新規APIキーや有料サービスは不要です。

## 単独で動作確認

Python 3.10以上と標準ライブラリだけを使います。以下はこのREADMEがあるフォルダで実行します。環境により`python`を既存の`python3`等へ置き換えてください。

```text
python scripts/evidence.py examples/ledger.json sample-output
python -B -m unittest discover -s tests -v
```

sample-outputは未作成のフォルダにします。成功時はverification.json、report.html、delta.jsonを出します。0は形式成功、1は入力・照合失敗、2は引数/出力先の問題です。1ならverification.jsonのpath/codeを確認します。既存出力は上書きしません。テストは作業ディレクトリ内に一時フォルダを作って削除します。

## 調査の準備と読み方

新しい調査フォルダへ必要な原文または短い抜粋を保存し、[台帳契約](references/ledger.md)に沿ってledger.jsonを作ります。架空例を実資料と混ぜないでください。未取得資料は所在だけ登録でき、本文根拠として使えません。

申告状態supportedと、リンクがacceptedとしてレビューされたことは別欄です。未レビューは未レビューとして残します。acceptedも担当の判断記録であり、機械が主張の真偽を保証した印ではありません。無関係な一致引用、反証の登録漏れ、原典系列の誤分類は自動検出できません。

baselineの比較は文字列・集合の差です。版の内容差や結論変更の原因は自動推論しません。実際の意味と理由を読み手が確かめます。1本の資料から導かれた複数記事を複数の独立証拠として数えないため、分かる依存元をderived_fromへ記録します。

生成レポートの「全記録」は調査台帳全体です。非公開資料、絶対パス、個人名、引用の権利を点検せず公開しないでください。配布物は汎用Skill・コード・テスト・架空例・説明だけです。
